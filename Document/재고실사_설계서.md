## 1. 목적과 범위

장부재고(TMASTOCK)와 실물 수량의 차이를 **통제된 절차**로 맞춘다.
실사 확정은 재고를 직접 고치지 않고, **차이만큼 수불(TMATRANS)을 만들어** 재고를 맞춘다(원장 불변 원칙 유지).

| 포함 | 제외(이번 범위 밖) |
|---|---|
| 실사 계획·대상 선정(스냅샷) | RFID/바코드 스캐너 연동(2단계) |
| 실사 수량 입력(초도/재실사) | 재고평가·원가 반영(수불에 단가 없음) |
| 차이 분석·승인·조정 확정 | 위치(loc_id) 단위 실사(현재 전 모듈이 loc_id=0 사용) |
| 실사 중 수불 통제(동결) | 자동 주기 스케줄링 |
| 조정 취소(역거래), 실사 현황/이력 | |

## 3. 프로세스 설계

### 3.1 전체 흐름

```
[실사계획 작성] → [대상 확정(스냅샷)] → [실사 진행 / 수량 입력] → [입력 완료] → [차이 검토/재실사] → [조정 승인] → [조정 확정] → 종료
     0 작성          1 대상확정            2 실사중                  3 입력완료         (재실사 → 2 복귀)     결재 E        C 확정
                                                                                                             ↘ 취소(역거래) → 3 복귀
```

| 단계 | 상태(stat_cd, MA0014) | 하는 일 | 통제 |
|---|---|---|---|
| ① 계획 | `0` 작성 | 실사명·기준일·대상 창고·품목 범위·실사 유형 지정 | 자유 수정 |
| ② 대상확정 | `1` 대상확정 | **그 시점의 TMASTOCK을 스냅샷으로 복사**(장부수량 고정) | 라인 **삭제만 가능**(상태 1~2, 이번 실사에서 빼고 싶은 라인). 계획 헤더 수정 불가 |
| ③ 실사 | `2` 실사중 | 현장 수량 입력(초도 → 필요 시 재실사). 입력자/일시 기록 | 동결 정책 적용(§3.3) |
| ④ 입력완료 | `3` 입력완료 | 입력 마감. 차이 자동 계산 | 수량 수정 불가(재실사 지시로만 재개) |
| ⑤ 검토 | `3` 유지 | 차이 리스트 검토, 차이 큰 라인 **재실사 지정** → 해당 라인만 `2`로 되돌려 재입력 | |
| ⑥ 승인 | 결재 AP0001 | 조정 승인(결재 사용 시). 사유 필수 | 상신 후 잠금 |
| ⑦ 확정 | `C` 확정 | 차이 라인마다 ADJ_IN/ADJ_OUT 수불 생성 + 재고 반영 | 되돌리기는 확정취소(역거래)만 |

### 3.3 실사 중 수불 통제 (동결) — **핵심 설계 결정**

실사 동안 재고가 움직이면 스냅샷과 현물이 어긋난다. 두 가지 방식 중 택일(기본 B 권장):

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 완전 동결 | 대상 창고의 입·출고/이동/생산 확정을 **서버가 거부** | 차이 해석 단순·정확 | 현업 운영 중단 |
| **B. 변동 보정(권장)** | 동결 없이, 스냅샷 이후 **확정된 수불을 차이 계산에 반영**: `조정대상 차이 = 실사수량 − (스냅샷수량 + 스냅샷 이후 순수불)` | 가동 중에도 실사 가능, 차이 왜곡 없음 | 계산 로직·설명 필요 |

- B는 수불이 `TMATRANS`에 `trans_id`(증가 번호)로 쌓여 있어 **스냅샷 시점 최대 trans_id를 헤더에 보관**하면 이후 수불은 `trans_id > snap_trans_id`로 정확히 합산 가능. (재고 변동이 큰 라인은 "변동있음" 표시)
- 사업장이 A를 원하면 `TSMPROCCONFIG`의 **시스템 설정(실사 동결 방식 A/B)**으로 선택하게 한다(입고방식과 같은 방식) → 시스템설정 후보 목록에 추가.
- A 선택 시 통제 지점: `USP_PR_TRANS_POST`와 각 확정 CORE가 공통으로 부르는 검사 함수 `FN_MA_STOCK_FROZEN(acc, wh)` 1개 추가(수불을 만드는 모든 경로가 이미 TMATRANS INSERT를 하므로 INSERT 트리거 대신 **공통 함수 호출**을 권장 — 트리거는 오류 메시지 제어·롤백 흐름이 불투명).

### 3.4 수량 입력 규칙

- **핵심 규칙: 선별(스냅샷)된 라인은 삭제하지 않는 한 전부 실사수량을 등록해야 하고, 전부 확정에 반영된다.** 예외·제외·일괄처리 없음. 장부수량과 같으면 같은 수량을 입력하면 되고(차이=조정수량 0, 수불 미생성), 0도 유효한 입력이다(빈칸=미입력). 빼고 싶은 라인은 삭제(상태 1~2)만 가능하며, 삭제된 라인은 이 실사에 존재하지 않는 것으로 본다.
- 입력 단위: 스냅샷 라인(품목·창고·LOT) 1행 = 실사 1행. 재고 행이 아예 없는 품목/LOT에 현물이 있는 경우를 위해 **라인 수동 추가**(상태 `2`에서만, "계획 외 발견"). 재고 행이 있는 0 재고 라인은 대상확정 때 자동으로 라인이 된다.
- **블라인드 카운트 옵션**(`blind_yn`): Y면 입력 화면에서 장부수량을 숨김(현장 편향 방지). 확정 단계(차이 검토)부터 공개.
- 초도 수량 `cnt_qty` / 재실사 수량 `recnt_qty` 분리 보관. **최종 실사수량 = 재실사가 있으면 재실사, 없으면 초도**.
- 입력자/입력일시는 라인별 기록(`cnt_user_id`, `cnt_dt`). 다중 인원 분담 입력 가능(라인 단위 락 없음, 마지막 저장 우선 + 이력 불필요 — 필요 시 2단계).
- LOT 관리 품목(`TBAITEM.lot_yn='Y'`)은 LOT 필수. 재고관리 안 하는 품목(`stock_yn='N'`)은 대상 제외.

### 3.5 차이 처리·조정

```
diff_qty   = 최종실사수량 − 기준장부수량          (+ : 실물이 많음 → ADJ_IN / − : 실물이 적음 → ADJ_OUT)
기준장부수량 = 스냅샷수량 + 스냅샷 이후 확정수불 순증감   (방식 B)  /  스냅샷수량 (방식 A)
```

| 항목 | 규칙 |
|---|---|
| 허용 오차 | 헤더 `tol_qty`/`tol_rate`(선택) 이내 차이는 "정상" 표시만, 조정은 선택 |
| 사유 | 차이 라인마다 **조정사유 필수**(`adj_reason`, MA0016: 분실/파손/오입고/계수착오/기타). 사유 없으면 확정 거부 |
| 승인 | 차이 라인이 1건이라도 있으면 결재 필수(설정 가능). 차이 0이면 결재 없이 확정 가능 |
| 확정 | 차이 ≠ 0 라인마다 `USP_PR_TRANS_POST`(ADJ_IN='I' / ADJ_OUT='O', src_type='STKCNT') 호출 → 라인에 `trans_id` 보관 |
| 확정취소 | 기타출고 CANCEL_CORE와 동일: 원 수불 반대 방향 행 추가(`org_trans_id`). **취소 시점 재고가 모자라 역거래(ADJ_OUT 취소=입고는 무관, ADJ_IN 취소=출고)가 불가하면 거부** |
| 재고 0 → 음수 | 조정 출고는 현재고 이상 불가(USP_PR_TRANS_POST 검증) — 방식 B에서 기준장부가 현재고와 달라도 **실제 TMASTOCK** 기준으로 최종 검증 |

#### 확정 CORE 로직(요약)

```
검증: 상태 3, 결재 사용설정이면 AP 상태 E(승인완료), 미입력 라인 없음(최종 실사수량 NULL인 라인이 하나라도 있으면 거부 — 예외 없음),
      차이≠0 라인의 adj_reason 필수, 방식 B면 move_qty 재계산 후 diff 재확인
BEGIN TRAN
  라인 순회(차이≠0, stock_yn='Y'):
    diff>0  → USP_PR_TRANS_POST kind='I', type='ADJ_IN',  qty=diff,  src_type='STKCNT', src_id=cnt_id, src_no, src_serl=serl, date=cnt_date
    diff<0  → USP_PR_TRANS_POST kind='O', type='ADJ_OUT', qty=-diff
    → 라인.trans_id = 새 trans_id
  헤더: stat_cd='C', cfm_*; 
COMMIT
```

> `USP_PR_TRANS_POST`는 loc_id를 0 고정으로 쓴다 — 현재 전 모듈 정책과 일치. 위치 실사가 필요해지면 그때 loc 인자 추가(현 설계는 loc_id 컬럼을 보존해 확장 가능).

| 같은 창고에 진행 중 실사가 이미 있음 | 대상확정 시 거부(창고 단위 단일 진행). 서로 다른 창고는 동시 가능 |
| 스냅샷 후 새 LOT 입고 | 라인 없음 → 실사 중 "추가 라인"으로 입력 가능. 방식 B는 move_qty로 반영 |
| 재고관리 안 하는 품목(stock_yn='N') | 대상에서 제외(수불은 있어도 재고 안 잡음) |
| 실사수량 미입력 라인 (`fin_qty IS NULL`) | **입력완료(`DONE`)에서 미입력 라인 목록과 함께 거부** + 확정에도 같은 검증(안전장치). 해결은 두 가지뿐: ① 수량 입력(0도 유효, 장부와 같으면 같은 수량 → 차이 0) ② 그 라인 삭제(상태 1~2에서만, 이번 실사에서 제외됨) |
| 차이 0 라인 | 정상 반영 대상이지만 확정 시 수불을 만들지 않는다(조정수량 0). 사유 입력 불필요 |
| 방치된 실사 문서 | 미확정은 재고/수불에 영향 없음. 같은 창고 단일 진행 제한 때문에 상태 1~3은 **취소(`X`)**로 창고를 풀고 이력으로 남김. 삭제는 상태 0만(다른 문서와 동일). 일괄 삭제 기능은 만들지 않음 |
| 확정 후 이미 재고가 사용돼 취소 불가 | 역거래 시 재고 음수가 되면 거부(기존 CANCEL_CORE와 동일 메시지 규칙) |
| 확정 취소 후 | 상태 3으로 복귀(재조정 가능). 확정 이력은 TMATRANS 역거래로 남음 |
| 외주처 창고(wh_type OS) | 대상 선택 가능(외주처 보유재고 실사). 단 TR(이동중)은 제외 — 이동 차이는 외주이전 `DIFF` 프로세스가 담당 |
| 동시성 | 라인 저장은 라인 단위(재고 락 아님), 확정만 `TMASTOCK UPDLOCK,HOLDLOCK`(TRANS_POST가 이미 수행) |
| 실사 도중 품목 마스터 재고관리 여부 변경 | 라인의 `stock_yn` 스냅샷으로 확정(기존 입고와 동일 원칙) |

## 7. 사용자 결정이 필요한 항목 (기본값 제안)

설계는 아래 기본값으로 진행 가능하고, 바꾸면 영향 범위만 수정합니다.

| # | 결정 | 제안 기본값 | 영향 |
|---|---|---|---|
| 1 | 실사 중 수불 방식 | **B 변동 보정**(동결 없음). 시스템설정으로 A 선택 가능하게 | 스냅샷 `snap_trans_id`·`move_qty` 계산 유무 |
| 2 | 조정 승인에 전자결재 필수? | 차이 있으면 필수(설정화) | AP0002 `STKCNT`, 확정 전 AP상태 검증 |
| 3 | 결재 승인 후 자동 확정 vs 별도 확정 버튼 | **별도 확정 버튼**(승인=허가, 확정=실행). 기존 "승인 후처리는 화면별로 사용자가 결정" 합의에 따라 `USP_AP_APPR_S_STKCNT` 후처리는 **비워 둠** | 결재 후처리 프로시저 |
| 4 | 블라인드 카운트 기본값 | 기본 N, 계획에서 선택 | 헤더 `blind_yn`만 |
| 5 | 미입력 라인 처리 | **확정된 규칙(2026-10-04)**: 선별된 라인은 삭제하지 않는 한 전부 입력·전부 반영. 미입력은 입력완료에서 거부(확정에도 안전장치), 해결은 입력 또는 라인 삭제뿐, 차이 0은 수불 미생성 | DONE·CONFIRM_CORE 검증, 라인 삭제 허용 상태(1~2) |
| 6 | 위치(loc) 단위 실사 | 이번 범위 제외(전 모듈 loc=0) | 키/컬럼은 보존해 확장 가능 |
| 7 | FADU 적용 시점 | DEV 선적용, 검증 후 FADU(DB 양쪽 마이그레이션 + 정적 복사) | 배포 절차 |
| 8 | 허용오차(tol) 사용 | 선택 입력(MVP에 포함) | 헤더 2컬럼, 화면 표시만 |

## 8. 구현 순서 제안
